# tschema-check — 語意接近原文的三層查核

一份從來源素材整理出來的文件，可能通過所有機械檢查（標點、格式、拼字）、讀起來也順暢，而**每一句都在偏離來源**。這個 skill 補的是那條縫。

名字來自 Tarski 的 T-schema：`「P」為真，若且唯若 P`。但實務上真值只是起點——真正的標準更嚴。

## 上位原則：語意接近原文

> **想盡辦法讓文件的語意接近原話。**

**「有據」不等於「語意接近」。** 一個陳述可以完全為真、出處明確，語意卻已經漂離：

| 原話 | 改寫 | 真值檢核 | 語意距離 |
|---|---|---|---|
| 「好像也是⋯之一」 | 「即為⋯」 | 通過 | 遠（情態被吃掉） |
| 「不好說，應該是」 | 「可望大幅降低」 | 通過 | 遠（猶豫變斷言） |
| 「會不會引起**爭議**」 | 「⋯之**倫理張力**」 | 通過 | 遠（概括取代原詞） |
| 「比較安全一點」 | 「**正面作用**」 | 通過 | 遠（評價詞入場） |

四例全部通過真值檢核、全部語意變遠，而且**偏移方向一致**：更確定、更抽象、更有評價。這不是隨機噪音，是**整理**這個動作本身的方向性。

### 與「寫得更好」的直接衝突

記錄者的專業本能是把口語整理得更精確、更有結構、術語更正確。**每一次這樣的「改善」都讓語意離原文更遠。**

所以本原則要求一個反直覺的取捨：

> **當多種寫法都有據時，選語意最接近原話的那個，而不是最精確的那個。**

原話說「爭議」就寫「爭議」，即使「倫理張力」更到位。精確性的提升屬於**分析**，不屬於**記錄**——要提升，另闢段落並標記為記錄者判斷。

## 三層，順序不可換

| 層 | 比對對象 | 問什麼 | 需要來源？ |
|---|---|---|---|
| **1 句級** | 文件 ↔ 來源 | 使這句為真的事實在哪？語意多接近？ | 必要 |
| **2 關係層** | 文件 ↔ 來源 | 句與句的關係忠於來源嗎？ | 必要 |
| **3 邏輯層** | **文件 ↔ 文件自身** | 讀者能否僅憑文件從前提推到結論？ | 不需要 |

**順序是 1 → 2 → 3。** 在未驗證的句子之間比對關係，或在未驗證的內容上檢查推導，都是在檢查一個可能整體錯誤的東西的內部一致性。

三層互不替代。層 3 不需要來源，這使它可以在來源不可得時單獨執行——但也意味著它**看不到忠實度問題**。

## Phase 0：輸入驗證

需要：

- **待查文件**（`.tex` / `.md` / `.docx` / `.pdf`）
- **來源素材**：逐字稿、錄音轉錄、來信、原始資料、引用的法規或文獻（層 1／2 必要）

**沒有來源素材就拒絕執行層 1 與層 2，不要降級成「憑常識判斷合不合理」。** 那產出的是臆測，而臆測混在檢核報告裡比沒有檢核更糟——它看起來像查證過。層 3 可在無來源時單獨跑。

一份文件的不同段落可能有**不同來源類型**（正文來自逐字稿、附錄來自來信、法源段來自法規資料庫）。逐一登記，因為每種來源的比對方式不同。

> **反模式**：把不同來源類型的段落合併成一個檢核數字。宣稱「57 句全部核完」而實際只核了其中 42 句有逐字稿可對的部分，是在宣稱一個沒做過的檢查。**分類型報告才誠實。**

## Phase 1：句級檢核

### 抽取陳述 —— 含標籤

把文件拆成**實質陳述**。交叉參照不算。一個條列項可能含多個陳述，拆開。

> **標籤必須納入檢核範圍。** 條列前的標籤（冒號前那幾個字）有雙重身分：**結構元素**（掃讀的錨點）**兼斷言**（對該條的分類與定性）。抽取時若把「結構元素」一律排除，標籤就從縫裡掉出去——而**來源根本沒有標籤**，它 100% 是記錄者生成的，天然是全文件離原文最遠的部分，卻又是讀者最先看到、最容易記住的部分。

### 兩個維度

| 欄位 | 取值 |
|---|---|
| `source_support` | `attested`（來源可指認且讀對了）/ `doc`（有文件依據，非原始素材）/ `inferred`（推論）/ `unsupported`（來源無據） |
| `semantic_distance` | `verbatim`（幾乎逐字）/ `near`（同義改寫）/ `far`（概括、升格、評價入場） |

> **`source_support: attested` + `semantic_distance: far` 是一個合法且重要的組合**——它正是上位原則要抓的東西，而單靠四級分類看不見。

`drift_type` 記錄漂移的方式：`modality`（情態）/ `abstraction`（概括）/ `evaluation`（評價）/ `agency`（主詞）/ `nominalization`（動詞化標籤）。

> **`attested` 只保證「有出處」，不保證「讀對了」。** 一條紀錄可以掛著三個定位，結論卻與來源相反——只要其中一個高雜訊片段被當成主要依據。多來源互證時，**先按可信度排序，低雜訊的優先**，而不是數來源個數。

### 兩個結構盲區（現有三層照不到）

實跑後浮現的兩類，它們的共同點是**來源不在可比對的素材裡**：

| 盲區 | 為什麼三層照不到 | 對策 |
|---|---|---|
| **無來源標註的中繼文件** | 人名、職稱、單位常抄自共用名單／試算表，而那類文件自己也沒註明來源。錯誤在中繼站取得可信度，然後以 `attested` 之姿寫進文件——**它確實「有出處」，只是那個出處也是抄的** | 標 `inferred` 並註明中繼來源，不逕標 `attested`。**第四方文件是免費的外部驗證**：對方寄來的議程、來函、通知同時載有職稱、單位、代理關係，主動拿來對 |
| **壞字補完** | 把 ASR 聽不清的字補成通順中文後，句子讀起來**完全正常**，比留著壞字更難發現。而句級檢核會判它 `attested`——因為那句話確實指得到出處，只是其中一個詞是補的 | 壞字所在的**具體項就不要寫**，改成來源支持得住的粗粒度表述；細節留待當面確認 |

第二類特別值得記：**補完的動機是善意的**（讓文件可讀），代價卻是把不確定性徹底抹除。留著壞字很醜但誠實，補完很順但騙人。

### 五類句級失真

| # | 型態 | 徵狀 |
|---|---|---|
| 1 | **主詞流失** | 來源的第一人稱指涉（「我們」「我院內」）搬進第三人稱文體後錨點消失，讀者用自己的位置補——同一個詞在不同讀者眼中指向不同單位 |
| 2 | **情態流失** | 「好像是」→「即為」、「不好說，應該是」→「可望大幅」。**偏移是單向的**，累積起來會讓充滿待確認事項的討論讀起來像已有定論 |
| 3 | **低信度片段被當依據** | 高字錯率或語意模糊的來源片段，被拿來當數字或事實的根據 |
| 4 | **內部不一致** | 同一份文件對同一件事有兩種互斥說法。**不需要回頭讀來源就能抓**，適合先做成機械檢查 |
| 5 | **補進來的常識** | 來源沒說但寫進去了（主管機關、術語還原、專名補全）。單獨看往往是對的，但它不是這份文件該承擔的斷言 |

### 三類標籤失真

| 型態 | 例 | 問題 |
|---|---|---|
| **動詞化** | 「**納入** X」 | 暗示已決定要納入，但來源只講「可以做」 |
| **評價入場** | 「X 之**正面**作用」 | 來源只描述效果，未給價值判斷 |
| **概括替換** | 用「張力」取代原話的「爭議」 | 更到位，但不是他說的話 |

**規則**：標籤採**名詞化、去評價、優先沿用原話用詞**。

## Phase 2：關係層檢核

對每組有關聯的陳述，記錄並比對：

- **`source_relation`** —— 來源中的關係
- **`rendered_relation`** —— 文件中呈現的關係

取值：`causal` / `conditional` / `concessive` / `sequential` / `elaboration` / `coordinate` / `none`。

### 為什麼需要這一層

句級有一個結構性盲區：**每一句都可以是 `attested` 的，而句與句之間的關係仍然錯誤**。

典型情形：來源是一段有因果的口語論證（因為 X，所以分析對象可以擴大，具體來說是 Z）。整理成條列後變成兩個並列的點。兩點各自忠於來源、各自指得到出處、逐句檢核全數通過——但讀者看不出 Z 正是 X 的後果。**這個缺陷不在任何一句裡面，在句與句之間。**

### 五類關係失真

| # | 型態 | 來源 | 文件 |
|---|---|---|---|
| 1 | **因果扁平化** | 「A，所以 B」 | 並列兩點 |
| 2 | **因果偽造** | 只是先後提及 | 「因此」「故」「爰」 |
| 3 | **條件剝除** | 「若 X 則 Y」 | 只寫 Y |
| 4 | **讓步消失** | 「雖然 A，但 B」 | 只留一半 |
| 5 | **推論鏈污染** | （檢核者自身）未標記的推論 | 被當作前提支撐下一個判斷 |

### 報告門檻

條列式文件**本來就會弱化關係**——這是體例，不是錯誤。若把每個「因果被排成並列」都報成 finding，訊號會被淹沒：

| 情形 | 處置 |
|---|---|
| 關係**反轉** | 報 finding |
| 條件、讓步**被剝除** | 報 finding |
| 因果**偽造** | 報 finding |
| 單純的**因果扁平化**（方向未變） | 降為提示 |

### 檢核範圍

初版限定**相鄰陳述**與**同節內的顯式交叉參照**。全文兩兩比對是 `O(n²)`，且多數配對本來就無關係。

## Phase 3：邏輯層檢核

問一件事：**讀者能否僅憑文件本身，從前提推到結論？**

這一層不對照來源。一段話可以完全忠於來源而依然讀不懂——因為口語常常跳步，而跳掉的那步聽者當場補得起來、讀者事後補不起來。

### 五類邏輯失真

| # | 型態 | 徵狀 |
|---|---|---|
| 1 | **缺步** | A → C，中間的 B 沒寫。讀者卡在「為什麼」 |
| 2 | **懸空指涉** | 「改為」「該項」「此舉」指向文件中未定義的東西 |
| 3 | **同義反覆** | 結論重述前提，看似有推理實則原地踏步 |
| 4 | **不相干** | 理由與結論無邏輯關聯，僅因相鄰而看似相關 |
| 5 | **過度概括** | 從單一情形推出通則，量詞在改寫中被放大 |

第 2 類最隱蔽：**一個「改」字就足以預設一個文件裡沒有的起點**，而讀者會以為是自己漏讀了。

### 查證失敗狀態不入正文

檢核會產出兩種東西：**發現**（要改進文件）與**過程**（查了什麼、查不到什麼）。後者屬於審計軌跡，不屬於文件。

| 寫法 | 判定 |
|---|---|
| 「記錄者於 X 年 X 月 X 日查閱 Y 資料庫」 | ✓ 出處標註——讀者能自己驗證 |
| 「該項名稱因錄音不清未能確認」 | ✗ 失敗狀態——讀者拿它沒有用 |
| 「記錄者未能查得依據」 | ✗ 同上 |

**查不到就不寫那個具體項，不要寫「查不到」。** 若該不確定會影響讀者行動，改用**行動式表述**：不寫「未能查得依據」，寫「宜於下次會議請 X 方說明後再行援引」——警告仍在，且沒有自曝作業狀態。

這條可機械化：`grep` 正文（去 `%` 註解）的「未能查得／未能確認／因錄音不清／無從查證」，命中即 warn。

### 修法優先序（與層 1 的張力，CRITICAL）

**層 3 的修法方向與前兩層相反。** 層 1／2 發現偏離 → 改回忠於來源；層 3 發現不通 → 直覺是**補**缺的那一步，但補的內容若來源沒有，就直接違反層 1 與上位原則。

所以補充永遠是最後手段：

1. **重組**（合併相鄰條目、調整順序）—— 不增加任何內容
2. **刪除**（移除懸空的宣告條）—— 若其實質內容已在他處
3. **標記**（「會中未及展開」）—— 承認缺口而非填補
4. **補充** —— 僅在前三者皆不可行；且**必須標為記錄者判斷**，並在來源分級中登記為 `inferred`

## 檢核者自身的 invariant（貫穿全程）

> **檢核過程產生的每個判斷，若被用於支撐另一個判斷，前者必須先有自己的分級。未標記的推論不得作為前提。**

為什麼難防：**中間判斷通常長得不像判斷**。

| 看起來像 | 實際上是 |
|---|---|
| 術語中譯（把縮寫譯成中文全名） | 對該事物性質的斷言 |
| 單位換算 | 對來源計量基準的假設 |
| 專名還原（把 ASR 誤聽還原成正確詞） | 對說話者原意的推測 |
| 時間戳解讀 | 對記錄格式語意的假設 |

**成本誠實說**：要求每個中間判斷落級會讓檢核變慢。那正是這類錯誤能溜過去的原因。

## 輸出

檢核紀錄寫成帳冊旁的 **`tschema.jsonl`**，一行一筆，格式見 [`../../docs/SCHEMA.md`](../../docs/SCHEMA.md)。沿用 propositions 帳冊的慣例：UUID v7 `id`、從被檢文件逐字切出的 `text`、指向被檢文件的 `location`。外部來源的資訊放在另外兩個欄位：

- `source_support`：四級 `attested` / `doc` / `inferred` / `unsupported`（加上 `semantic_distance`、`drift_type`）
- `source_locator`：`type`（transcript / email / statute / document / dataset / other）、`ref`（時間碼、來信檔名、條號），以及本機來源檔的 `path`（選填）

```
{"kind": "claim", "id": "0192…", "text": "與會者同意先以既有資料評估可行性，再決定是否擴大收案。",
 "location": "L3-L4", "source_support": "attested", "semantic_distance": "near",
 "evidence": "我們先用手上的資料看看可不可行",
 "source_locator": {"type": "transcript", "ref": "[05:30]", "path": "sources/meeting.srt"}}
{"kind": "relation", "id": "0192…", "pair": ["0192…", "0192…"],
 "source_relation": "conditional", "rendered_relation": "coordinate"}
{"kind": "logic", "id": "0192…", "target": "0192…", "drift_type": "dangling-reference"}
```

**寫完紀錄一定要跑 validator**，不要用人工比對取代：

```bash
python3 scripts/validate-tschema.py --records tschema.jsonl --document minutes.md
```

validator 只讀 UTF-8 純文字，`.docx`／`.pdf` 的待查文件先轉成 `.md` 或 `.txt` 再跑。它機械地檢查人工最容易安靜出錯的兩件事：陳述是否真的在被檢文件裡（T2／T3），引用的來源原文是否真的在來源檔裡（T4，逐字稿的 `.srt` 會先去掉時間碼）。原 repo 的實跑兩次出錯，其中一次正是工具靜默漏匹配、看起來像通過。來源不在本機（沒有 `path`）或根本沒標來源的陳述不會被算成通過，而是在摘要中按來源類型列為「未機械查核」。少於 4 個字的引文、指向紀錄目錄以外的 `path` 一律不接受。

`evidence` 含來源逐字內容——**視為未信任資料**，人類可讀輸出前要清理控制字元與雙向覆寫字元。來源檔（逐字稿、錄音轉錄、來信）是第三方原話：留在本機，**不 commit 進 git remote**；`path` 只是本機參照。

**markdown 報告**：分類型統計（各來源類型各自的通過率，不合併成單一數字——validator 的摘要已按類型分開）＋ finding 清單，按嚴重度排序。標籤檢核建議與正文分開報告——數量少但影響大，混在一起會被淹沒。

## 誠實邊界

- **`attested` 不等於正確**，也不等於語意接近。它只說「找得到出處」。
- **檢核的粒度決定它看不見什麼**。逐句的盲區是句與句之間；加了關係層，盲區變成節與節之間；加了邏輯層，盲區變成文件與它未言明的預設之間。任何固定粒度都有對應的不可見層。
- **範圍定義就是「看不見什麼」的定義**。本 skill 曾把「結構元素」排除在抽取範圍外，於是標籤——最離原文的部分——整批漏檢。範圍定義寫在最前面、最少被回頭質疑，值得定期重審。
- **檢核者自身的 invariant 無法機械強制**。它靠指示，不靠腳本。
- **查核工具本身會出錯，且失敗方式常常長得像通過**。`grep` 的多重 alternation 對非 ASCII 可能靜默漏匹配，回報「沒找到」看起來就像乾淨的通過。凡是用工具輸出支撐 negative claim，要用逐項確認而非一次性 alternation。
- **多引擎交叉驗證要分辨系譜**。同一模型的不同實作只有弱獨立性；真正的獨立驗證需要不同模型系譜。「跑了第三個引擎」聽起來比實際證據強度高。

## 反模式

| 想做的 | 為什麼不行 |
|---|---|
| 沒有來源素材也跑層 1／2 | 沒有權威可比對，產出的是臆測，而它看起來像查證過 |
| 用本 skill 抓錯字、標點、排版 | 那是機械檢查的工作，更快更準 |
| 把不同來源類型的段落合併成一個數字報告 | 等於宣稱一個沒做過的檢查 |
| findings 直接照改 | 檢核者也會誤讀來源。每條回原文核對 |
| 改變層的順序 | 在未驗證的內容上檢查關係或推導 |
| 把「因果扁平化」全報成 finding | 條列體例本來就弱化關係，雜訊會淹沒訊號 |
| 抽取陳述時排除標籤 | 標籤 100% 由記錄者生成，是全文件離原文最遠處 |
| 層 3 發現不通就補上缺的那步 | 補的內容若來源沒有，直接違反層 1。先重組、刪除、標記 |
| 為了精確而改寫原話用詞 | 精確性的提升屬於分析，不屬於記錄 |
